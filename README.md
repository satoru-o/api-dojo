# api-dojo

1問だけ、APIクライアントを書く練習をする「今日は1問だけ」ツールです（[python-dojo](../python-dojo) 姉妹版）。
実在の外部APIではなく、リポジトリに同梱した疑似APIサーバー（標準ライブラリの `http.server` のみ、
外部フレームワーク不使用）を相手に、[requests](https://requests.readthedocs.io/) ライブラリで
リクエストを送るクライアントコードを書きます。疑似APIサーバーは `check` 実行時にdojo.pyが
裏で自動的に起動・停止するので、**自分でサーバーを起動する必要はありません。**

実行には [uv](https://docs.astral.sh/uv/) を使います。`dojo.py` の先頭にインライン依存定義
（PEP 723）が書いてあるので、`uv run dojo.py ...` を実行するだけで `requests` を含む
必要なパッケージが自動的に用意されます。

> [!NOTE]
> このリポジトリは個人の学習記録です。フォーク・Star等は自由にどうぞですが、
> PR・Issueは受け付けていません。

## 基本の使い方

```
uv run dojo.py today   # 今日の問題を表示する（すでに出題中ならそれをもう一度表示）
$EDITOR workspace/answer.py   # 自分の手で答えを書く
uv run dojo.py check   # 採点する（何度でも再実行OK、失敗してもペナルティなし）
```

これで合格すると、次に `uv run dojo.py today` を実行したときに次の問題が出題されます。
「1問だけ」出題する設計なので、今の問題を解く（または `skip` する）まで次には進めません。

## その他のコマンド

```
uv run dojo.py hint       # 今日の問題のヒントを表示
uv run dojo.py answer     # 模範解答を表示（誤って見ないよう確認プロンプトあり）
uv run dojo.py skip       # どうしても詰まったら今日の問題をスキップして次へ
uv run dojo.py show 003   # 過去/任意の問題文を読み返す（状態は変えない）
uv run dojo.py log        # 進捗サマリを表示
uv run dojo.py today --random   # 解答済みの問題からランダムに復習出題
```

## 疑似APIサーバーの仕様

問題を解く前に **[docs/api_reference.md](docs/api_reference.md)** を読んでください。
エンドポイント一覧、認証トークン、ページネーション、エラー・レート制限・タイムアウトの
挙動がまとまっています（実在のAPIドキュメントを読む練習も兼ねています）。

## 出題トピック

| 問題 | トピック |
|---|---|
| 001 | GETリクエストの基本 |
| 002 | クエリパラメータ付きGET（ページネーションパラメータ） |
| 003 | POSTでJSONボディを送信 |
| 004 | リクエストヘッダー（Authorization）による認証 |
| 005 | ステータスコードによる分岐処理 |
| 006 | エラーレスポンスのハンドリング（リトライ、例外の伝播） |
| 007 | 複数ページにまたがるレスポンスの全件取得 |
| 008 | レート制限（429 + Retry-After）対応 |
| 009 | タイムアウト処理 |
| 010 | 複合問題（認証 + ページネーション + エラーハンドリング） |

全問題は `check.mode: "client"` という共通の採点方式です。`workspace/answer.py` に
指定された名前の関数を定義すると、dojo.pyがその関数の第一引数として自動的に
`base_url`（疑似APIサーバーのURL）を渡して呼び出し、戻り値（または送出された例外）を
期待値と比較します。「リトライを使い切っても失敗したら例外をそのまま上位に伝播させる」
という設計（辞書に変換して握りつぶさない）を一貫して採用しています。

## ディレクトリ構成

- `server/pseudo_api.py` — 疑似APIサーバー本体。`docs/api_reference.md` が仕様書、
  こちらが実装。
- `problems/NNN_.../` — 問題ごとのフォルダ。`problem.json`（お題文とチェック方法）、
  `hint.md`（ヒント）、`solution.py`（模範解答）。`hint`/`answer` コマンド以外ではこれらの
  ファイルは開かないので、`today`/`check` を使う限り誤ってネタバレしません。
- `workspace/answer.py` — 自分が書く答案。常にこの1ファイルだけを使います。
- `state/today.json` — 現在出題中の問題と状態（assigned/solved/skipped）。
- `state/progress.jsonl` — 解答記録（1行1JSON、追記のみ）。

## 注意

- `problems/*/solution.py` には模範解答がそのまま書かれています。このリポジトリを公開する
  場合は、答えが誰でも見える点に留意してください。
- 疑似APIサーバーの一部エンドポイント（レート制限・タイムアウト）は意図的に数秒待たせる
  ため、該当する問題の `check` は数秒かかります。
